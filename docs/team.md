# 팀 & 오너십 (Team & Ownership)

팀원, 컨텍스트 오너십, 협업(커밋/PR/브랜치) 규칙을 정의한다.

---

## 1. 팀원 및 컨텍스트 오너십

| 이름 | 역할 | 오너 컨텍스트 |
|---|---|---|
| **준호** | 백엔드 리드 / 프론트엔드 | **Report**, 공통(`global`) |
| **최지원** | 백엔드 | **Auth**, **Profile** |
| **배서연** | 백엔드 | **Matching** (`match`) |
| **윤세윤** | 백엔드 | **Chat** |

- "오너"는 해당 컨텍스트의 설계·구현·리뷰 1차 책임자를 뜻한다.
- 컨텍스트 경계를 넘는 변경(인터페이스/이벤트 계약 변경 등)은 **관련 컨텍스트 오너 간 협의** 후 진행한다.
- 컨텍스트별 책임 범위는 [domain-design.md](domain-design.md) 참조.

---

## 2. 커밋 / PR 규칙

- **커밋과 PR은 담당 컨텍스트 기준으로 나누는 것을 권장**한다. (한 PR에 여러 컨텍스트의 변경을 섞지 않는다.)
- PR은 해당 컨텍스트 오너(또는 백엔드 리드)의 리뷰를 거친다.
- 공통(`global`) 변경은 영향 범위가 넓으므로, 변경 시 팀에 공유하고 리드 리뷰를 받는다.

---

## 3. 브랜치 전략 (현재 관행 기준)

- 통합 브랜치: **`develop`** (현재 main 브랜치).
- 기능 작업은 **컨텍스트/기능 단위 feature 브랜치**(예: `feat/global`, `feat/auth`)에서 진행 후 `develop`으로 PR.
  - (참고: 초기에 `feat/global` → `develop` PR(#1)이 머지된 이력이 있다.)
- 컨벤션상 브랜치명은 `feat/<context>` 형태를 권장한다.

> 위 브랜치 규칙은 현재 레포의 커밋/머지 이력에서 관찰된 관행을 정리한 것이다. 팀 합의로 변경 가능하며, 변경 시 본 문서를 갱신한다.

---

## 4. 문서 오너십

- 본 `docs/`와 `CLAUDE.md`는 팀 공통 문서다.
- 정책·설계 변경 시 코드와 함께 해당 문서를 갱신한다(특히 [open-decisions.md](open-decisions.md)의 항목이 확정되면 즉시 반영).
